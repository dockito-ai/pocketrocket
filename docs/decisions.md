# Decisions

Numbered, dated, newest last. These win over the BRD when they disagree.

1. **29 Oct 2026. Name: PocketRocket.** Repo `ShankarKakumani/pocketrocket`, Dockito project `pocketrocket`.
2. **29 Oct 2026. Package id stays `com.termux`.** Termux's prebuilt packages and bootstrap hardcode `/data/data/com.termux/files/usr`; a new id would need the whole package set rebuilt. Only the visible name, icon and notification change. Stock Termux cannot be installed alongside; fine for one phone.
3. **29 Oct 2026. Claude Code is downloaded at first run, never bundled.** From `downloads.claude.ai`, checked against Anthropic's manifest. Always current, nothing of Anthropic's redistributed.
4. **29 Oct 2026. Fork Termux, build nothing from scratch.** No own terminal, no own rootfs, no own OS. The job is wrapping what exists.
5. **29 Oct 2026. DNS preload to Google is off by default.** The community script forces 8.8.8.8 to avoid a connection hang; here it is a Settings toggle so private DNS and VPN resolvers are respected.
6. **29 Oct 2026. Phone is the machine.** Local sessions only; no cloud sessions, no Remote Control as the main path. Shankar uses it at stops with a keyboard, never while driving.
7. **29 Oct 2026. Every session reports its state.** Working, needs input, done or error, shown as a dot on each tab, an overview when the app opens, and a notification when a session needs input or finishes. Driven by Claude Code hooks writing status files the app watches. Built as T7, right after tabs.
8. **29 Oct 2026. Keep-alive is best effort.** No start on boot, no 24/7. We do what Android allows; if the app is killed or swiped away, Shankar reopens it and resumes the sessions himself.
9. **29 Oct 2026. No browser for agents for now.** The WebView/CDP bridge and proot Chromium are out of scope. The app is a terminal, git and dev CLIs.
10. **29 Oct 2026. Shankar's dev tools install once at first run.** For now: Claude Code, git, node and npm, all already in the base setup. More later, through `~/.pocketrocket/tools.txt` (read by setup) and a Tools screen to search and install packages, which also adds them to that file.
11. **29 Oct 2026. Native app UI around the terminal.** Setup, overview, Tools, profiles, GitHub and Settings are polished Compose screens with real progress, not terminal output; the terminal is reserved for sessions. The Termux welcome text is replaced with a PocketRocket one.
12. **29 Oct 2026. Independent work may run in parallel.** Still one agent per piece; pieces that don't share files run side by side.
13. **29 Oct 2026. minSdk 24.** Compose needs 23 and the apt-android-7 bootstrap needs Android 7; only Android 16 matters anyway.
14. **29 Oct 2026. Built for many sessions from day one.** A session manager in the foreground service owns every session and its live state; Home is a grid of session cards with state (working, waiting, done, error); one-gesture switching between sessions. Claude sign-in uses the subscription through the official OAuth flow in a Chrome Custom Tab sheet.
15. **29 Oct 2026. Dictation through Android, not Claude Code.** A mic button beside the chat box uses Android's SpeechRecognizer (on-device where available) and fills the box for editing; nothing is sent automatically. Built right after the chat sessions merge.
16. **29 Oct 2026. Sessions are chat-first.** Each session is the real Claude Code CLI in stream-json mode (`--permission-prompt-tool stdio` is required for permission prompts) driven by a native chat UI; the terminal stays one tap away as the fallback. Proven with two parallel real sessions on the emulator.
17. **29 Oct 2026. Claude controls belong in the chat UI.** Model, permission mode, context meter, plan usage and slash commands are first-class controls, driven through the stream-json control protocol and the CLI's own reports; built right after persistence and dictation merge.
18. **29 Oct 2026. Projects are the way into work.** Folders live under `~/projects`. Sessions start from a project; the grid shows which project each session is in. Bottom nav becomes Sessions, Projects, Settings (Tools moves into Settings). Shankar chooses the folder structure; Claude launches in any folder. This is where the workflow starts, so GitHub + Projects is built next, before Claude controls.
19. **29 Oct 2026. Workspaces hold repos and sessions.** A workspace is a folder that may contain several repos; it opens as tabs of Claude sessions (cmux-style) plus a Git panel per repo and GitHub-mobile-style read-only browsing (tree, file view, diffs, commits). Every session has a status line: folder, branch, model, context used, mode. Git data comes from the git CLI first; native modules (Rust) only if measurements show it is too slow.
20. **29 Oct 2026. Accounts are set per workspace.** Settings holds many Claude subscriptions and many GitHub accounts, each with a default. Creating a workspace preselects the defaults and lets them be changed; workspace settings can change them later. Sessions inherit the workspace's Claude account (overridable per session); repos in a workspace use its GitHub key, gh config and commit identity.
21. **29 Oct 2026. How per-workspace accounts are wired.** Claude: each session is launched with `CLAUDE_CONFIG_DIR` set to its account's folder. Git identity and SSH key: `~/.gitconfig` gets an `includeIf "gitdir:<workspace>/"` per workspace pointing at that GitHub account's config (`user.name`, `user.email`, `core.sshCommand` with its own key and `IdentitiesOnly=yes`), so every git command in that folder, from the app, Claude or a terminal, uses it. gh: one `GH_CONFIG_DIR` per GitHub account, set in the environment of every session and terminal in the workspace (never the global `gh auth switch`, which would affect parallel sessions).
22. **29 Oct 2026. A Health screen in Settings.** Every permission and keep-alive setting the app depends on is checked there, with a Fix button that opens the right system screen, plus when and why Android last stopped the app (ApplicationExitInfo). Settings shows a warning row when anything needs attention. Built with keep-alive (T8).
23. **29 Oct 2026. Screens are built exactly as the mockup.** `docs/ux-mockup/` is the spec for every screen: layout, wording, spacing and colours are copied as they are, not reinterpreted. Existing screens (Home, chat, New session) are restyled to match.
24. **29 Oct 2026. Attachments through a "+" sheet.** The chat composer's "/" button becomes "+", opening Photos, Files, Camera, Commands and recent screenshots (Option A in `docs/ux-mockup/Attachments.html`); "/" typed in the field still opens commands. Attachments are copied to `~/.pocketrocket/attachments/` for now; images and PDFs are sent inside the stream-json message, other files by path.
25. **29 Oct 2026. Sessions can be named and renamed.** New session has an optional Name field (blank keeps the folder name); later, long-press its card on Home (Rename or End session) or its chip in the session switcher to rename it. The name is the app's own (saved in `sessions.json`), not Claude Code's conversation title.
26. **29 Oct 2026. The app updates itself from a button, not automatically.** Settings shows the installed PocketRocket version and the latest GitHub release; tapping Update downloads the APK with the connected GitHub account's gh login (the repo is private), checks its SHA-256 and hands it to Android's installer. Nothing downloads or installs on its own. Releases keep being built on the Mac with its debug key so updates install over the current app without wiping data; a release key and CI builds can come later.
27. **29 Oct 2026. Branches, a commit graph and pull requests in the repo's Git screen.** Reached from Workspace → repo card (which shows open PRs and review requests); in a session only the branch in the status line is tappable and opens that repo's branch sheet. The branch card's ▾ opens the branches (local, then GitHub-only; switch with a stash prompt and a warning when a session is working in the folder; new branch; new session on a branch in a git worktree). The Commits tab becomes Graph (lanes, branch and PR labels, this branch or all; long-press a commit to check out, branch, open its PR, copy SHA). A PRs tab lists the repo's PRs (Open, Mine, To review, Closed) with checks and reviews; a PR shows overview, files in the existing diff viewer and commits, with Check out, Review with Claude and Merge. No PR creation in the app (Claude or GitHub does that); no line comments or approvals yet. Uses `git` and the workspace account's `gh`. Mockup: `docs/ux-mockup/BranchesPRs.html`.
28. **29 Oct 2026. Subagent numbers in the chat.** Each agent card shows elapsed time (ticking while it runs), tokens and tool calls, frozen when it ends; the status line under the chat box shows "N agents" while any run, tapping scrolls to them.
29. **29 Oct 2026. Edit and Retry on your messages.** Long-press a message: Edit (rewind at once, no dialog, text and attachments back in the chat box, keyboard open, with an Undo snackbar), Retry (rewind and send the same message again), Copy. While Claude is working, Edit and Retry stop it first.
30. **29 Oct 2026. Code stays private, releases are public.** Release APKs are published in the public repo `ShankarKakumani/pocketrocket-releases` (README and APKs only); the in-app updater reads it without a GitHub login. This repo stays private for now; making it public is revisited later (Termux is GPLv3, so sharing builds widely means sharing source). Releases are signed with PocketRocket's own release key: keystore at `~/.pocketrocket-keys/pocketrocket-release.jks` on the Mac with a copy in iCloud Drive (`PocketRocket Keys/`), password in the Keychain, never in the repo.
31. **29 Oct 2026. Clone as any connected GitHub account.** The account in the clone screen's top bar is a switcher when more than one is connected (default and this folder's are marked). Switching lists that account's repos and clones with its key and gh login; a repo cloned as another account than its workspace's is bound to that account, so later push, pull and gh in it use the same account.
32. **29 Oct 2026. Model and mode are picked when starting, sessions end from the chat too.** New session has real Model and Mode pickers; they start as Default (the account's model) and Manual, as before. The model list is the one Claude Code last reported, else Default / Opus / Sonnet / Haiku. Both apply as the process starts and can still be changed in the session. Long-press a chip in the session switcher for Rename and End session (same confirmation as Home).
33. **30 Oct 2026. Inside a session, the switcher shows only that workspace.** The chips and swipe in the session view list the sessions whose folder is in the same workspace as the one opened (its repos and their `.worktrees`), or the same folder when it is in no workspace. Home still shows every session.
34. **30 Oct 2026. Messages sent while Claude works wait in a Queued box.** Like Claude Code's own queued prompt: the message waits above the chat box and joins the chat only when Claude reads it (at its next step or the end of the turn), so it never gets mixed into a reply that is still streaming. The long-press menu on your messages is Edit and Retry; Copy is dropped.
35. **30 Oct 2026. Android's process limit is optional.** Lifting it needs Developer options, which Shankar keeps off. Leaving it on is fine: it protects the phone from lagging or freezing, and PocketRocket is a companion to the laptop, not a full workstation, so an occasional stopped session is acceptable. The Health row stays, with its guide, but is shown muted as optional and no longer counts toward the Settings warning or the keep-alive banner.
36. **29 Oct 2026. Own package id `app.pocket`, still on Termux's packages.** Replaces decision 2; the spike passed and was merged on 30 Oct 2026. The id is exactly as long as `com.termux`, so `/data/data/com.termux` is swapped byte for byte for `/data/data/app.pocket` in the bootstrap at first run and in every package apt downloads (after its signature is checked, before dpkg installs it). Termux's own mirrors and full catalog stay; nothing is rebuilt or hosted by us. Proven first in a spike on the emulator (Claude session, git push, gh, ssh, a few extra packages); if something can't be made to work, we report back before going further. Installs as a new app, so the phone needs one fresh setup; it can sit beside stock Termux.
37. **30 Oct 2026. Claude gets a browser to test pages it builds.** Replaces decision 9 for this one use: Claude opens its own dev servers, takes screenshots at phone and desktop widths, reads console and network errors and clicks through flows, through standard tools (Chrome DevTools MCP, Playwright where it works). Driving Shankar's logged-in browser on real sites (Claude in Chrome style) stays out of scope. It is an optional tool: offered as a step in first-run setup (with its size shown) and installable or removable later from Settings → Tools; once installed it is wired into every Claude account. It ships with the `app.pocket` build, so the one fresh setup that build needs can already include it. Shankar chose the engine on 30 Oct 2026, after the spike in `docs/web-testing-spike.md`: headless Chromium from Termux's x11 repository. The phone has the RAM and the disk, and the tool is optional, so the size is fine. The WebView is not used. Every WebView in the app shares one renderer, so sessions would take each other's page. Each Claude session gets its own Chromium through Chrome DevTools MCP (`--isolated`), with `--no-sandbox` and `--disable-gpu`, which is what ran under Termux. Phone, tablet and desktop widths are viewport emulation.
38. **30 Oct 2026. Dockito accounts like GitHub.** Settings › Dockito installs and updates Dockito's CLI (downloaded from Dockito's Homebrew tap release and checked against the formula's sha256, never bundled, run through the same glibc launcher as Claude Code), and holds its accounts with a default; a workspace can pick its own. Since the CLI has its own accounts (0.0.1-beta.27, now the minimum), PocketRocket uses them: one shared DOCKITO_CONFIG_DIR, the list from `dockito accounts`, the default is the CLI's login in use, and a workspace's pick is its email, passed as DOCKITO_ACCOUNT. Workspace account pickers (Claude, GitHub, Dockito) are dropdowns, so they fit any number of accounts. Its skill is added to every Claude account. Not part of the first-run setup.
39. **30 Oct 2026. Tools is a list of tiles, each with its own page.** Tools is a list of tiles, each showing the tool's name, status and size; tapping one opens a full-screen tool page with what it does, its sizes, and Install, Uninstall or Retry with progress. Tools has no bottom nav. Mockup `docs/ux-mockup/Tools.dc.html`. In Settings, Tools is the first row under APP and shows how many tools are installed; the unused Default model and mode row is gone. Every Settings row that opens or changes something ends its value with "›" (Theme, Claude Code and PocketRocket included).
40. **30 Oct 2026. First-run setup installs Dockito, never Chromium.** Dockito's CLI becomes a mandatory first-run step (downloaded from Dockito's Homebrew tap release and checked against the formula's sha256, as in decision 38; still never bundled). Dockito works like Claude Code and git: first-run setup installs it and the app never installs it from anywhere else. Settings › Dockito: accounts; updates live on the Updates screen (decision 41). Settings › Dockito never does a first install; a missing CLI says "Not installed. Run setup again.", as the Claude Code page does. Headless Chrome is no longer offered during setup at all; it is installed only from Settings → Tools (amends decision 37).
41. **30 Oct 2026. Updates screen.** Settings has one Updates row; the Updates page lists PocketRocket, Claude Code, Git and Dockito with version, status and Update; Settings › Dockito and the Claude Code page no longer hold update UI. The row shows a count when something is out of date ("1 update ›"). The page is full screen with no bottom nav, like Tools, with Check now (rechecks all four, "Checked 2 min ago") and Update all when more than one needs updating; a running update shows its steps and live progress as a tool page does. PocketRocket uses the in-app updater, Claude Code the existing check, Git updates through apt, Dockito through the Homebrew tap formula as `Dockito.install` does. Mockup `docs/ux-mockup/Updates.dc.html`.
42. **30 Oct 2026. Cloning runs in the background with a progress notification; one clone at a time, the clone screen is locked while it runs.** The clone belongs to the app (`CloneManager`, kept alive by a small foreground service, `CloneService`), not to the screen: back and Home work as usual and git keeps going. The notification reads "Cloning owner/repo · 42%" with Cancel, then "Cloned owner/repo" or "Couldn't clone owner/repo" with Retry; tapping opens the repo's workspace, or the clone screen at the error. While a clone runs the clone screen shows only its progress and Cancel (no search, no second clone). The queue has one slot for now and is built so more can be allowed later.
43. **30 Oct 2026. Claude Code's setup is configurable in the app.** MCP servers, connectors, plugins and the rest of Claude Code's setup are managed from PocketRocket as far as Claude Code allows, per Claude account; what it doesn't allow stays in the terminal or links out. Plan and limits in `docs/claude-config.md`.
44. **30 Oct 2026. Conversations stay on their account.** An old session or earlier conversation resumes on the account it started on. There is no switching it to another account.
45. **31 Oct 2026. Android apps build and test on the phone, as two optional tools.** Both are installed only from Settings → Tools; nothing is added to first-run setup and nothing is bundled in the APK, everything is downloaded at install time. Two tiles, because building needs no Developer options: "Android" and "Device testing". Developer options are acceptable for Device testing only; decision 35 still holds for everything else. There is no emulator on the phone: testing runs on the real phone on a hidden virtual display. The user reads and accepts Google's SDK license on the tool page before anything downloads. Native NDK builds are out of scope. Android build is `docs/android-build.md`; Device testing is designed in `docs/device-testing.md`, not built. Measurements: `docs/android-tools-spike.md`.
46. **31 Oct 2026. Tap the Queued box to post now.** Like ctrl+enter in Claude Code: the whole box is the button, labelled "Queued · tap to post now", and all waiting messages go at once. No separate button and no keyboard shortcut. Claude Code decides how the running turn makes way, which can stop a running command.
47. **31 Oct 2026. Battery figures may use Developer options and adb grants.** Shankar agreed to turn on Developer options and grant permissions over adb so Settings › Usage can show the app's real battery use, a change from his position in decision 35, whose optional process-limit row stays as it is. The grants are `android.permission.DUMP` and `android.permission.PACKAGE_USAGE_STATS`; the app reads `dumpsys batterystats --charged` and shows its own line. `BATTERY_STATS` isn't needed. `BatteryStatsManager.getBatteryUsageStats` isn't used: Android blocks it as a hidden API for a normal app, and it only answers inside PocketRocket because of upstream Termux's hidden-API exemption. Without the grants the screen shows a guide, CPU time and App details. The grants apply to everything running in the app's uid, Claude Code included, and the guide says so.
48. **31 Oct 2026. New session starts in Auto, and the first message can have attachments.** The Mode picker in New session now starts on Auto, replacing Manual from decision 32; it can still be changed there or in the session. Other ways of starting a session (Git screen, a new session from the status sheet) stay on Manual. The first message has the chat's "+" (Photos, Files, Camera, recent screenshots, no Commands), and files picked there are dropped if the session is never started.
49. **31 Oct 2026. Wrangler is an optional tool for deploying and managing Workers, without local dev.** A tile in Settings → Tools installs Cloudflare's CLI from npm at a pinned version, 78 MB download, 62 MB on the phone; nothing is bundled and first-run setup never touches it. Node already comes with the base set, so the tool installs no packages. `wrangler dev` is left out because workerd has no Android build, and the page says so; there are no workarounds that make extra work for the user. Wrangler won't start on Android as published, because workerd's loader throws at startup, so the install runs npm with `--ignore-scripts`, adds one line to that loader to point it at a stub that says local dev isn't available, and sets the launcher's interpreter to the app's Node. The version is pinned, and the install fails plainly if the loader isn't the one it knows. The page has Log in and Log out. Log in runs `wrangler login --browser=false` and opens the phone's browser on its address. The token stays in Wrangler's own config file. The address stays only in the live log, and Wrangler's debug log for that run goes to a temp folder deleted afterwards. Uninstall signs out and removes `~/.config/.wrangler`.
50. **31 Oct 2026. Android NDK is its own optional tile, on top of the Android tool.** Shankar confirmed it and accepts it may not work on every project ("if it works, it works"). Termux's clang, CMake, Ninja and ndk-sysroot behind folders laid out as the NDK; it is not Google's NDK, which has no arm64 build. Install needs the Android tool, and uninstalling the Android tool removes this one too, with the confirm sheet saying so. Projects needing different NDK versions: one shim served under the default NDK version of each current Android Gradle Plugin, so pins are accepted but every version is the same Termux compiler, and the page says so. A version not listed stops the build with a clear message, never a download of Google's x86_64 NDK. Limits stated on the page: arm64 only, `c++_shared` only, no `ndk-build`, links against the phone's system libraries, Play releases built with Google's real NDK. Details in `docs/android-build.md`.
51. **31 Oct 2026. A voice assistant, not a launcher.** Shankar wants an assistant he can speak to: ask for status, hear announcements, allow or deny requests, unblock a waiting session, start agents. It uses his Claude subscription through Claude Code itself, with no API key. He dropped the launcher idea, so the launcher, home screen widget and control of other apps are not being built, and decision 37 stands. Voice moves out of "Not now"; Android Auto stays later. Plan and open points in `docs/assistant.md`.
52. **31 Oct 2026. Rocket gets the first tab.** The assistant is called Rocket and has its own screen, first in the bottom bar, where the app opens. There's no Rocket mic on Sessions or inside a chat; the composer mic stays dictation only. A sliders button on the Rocket screen opens quick controls in the style of the session controls sheet: tiles that light up for Hey Rocket, Announcements, Speaker and Quiet for 1 hour, plus login, memory and links. A popup stays for the lock screen, power button and wake word. Settings › Assistant has an on/off switch (off removes the tab and runs nothing) and a Claude login picker. Answers too long to speak go on screen as cards. Existing screens keep their look; the design boards for them are not a redesign. `docs/assistant.md`.
53. **31 Oct 2026. Backup and restore.** Shankar reinstalls often while testing and doesn't want to redo his setup. Settings › Backup keeps a single file, `Downloads/PocketRocket/pocketrocket.backup`, replaced only after the new one is written and checked, so a failed backup keeps the old one. Backup and restore both show real progress. It only backs up, and the app offers no uninstall. First-run setup stays unchanged and offers no restore. Nothing restores itself: he signs in first, then restores by hand from Settings › Backup › Restore. The backup holds workspaces (repos and folders without `node_modules` and build folders, names, per-workspace accounts), the inner config for Claude (settings, `CLAUDE.md`, skills, plugins, MCP servers, per-project memory), Git and Dockito, and the logins for Claude, GitHub and Dockito. Chats and tools are left out: chat history is not restored, and tools are downloaded again by hand. The whole file is encrypted with a passphrase. This is the one exception to logins staying only in their normal config files. Plan in `docs/backup-restore.md`.
54. **31 Oct 2026. Rocket's defaults and limits.** "Hey Rocket", listening while a session runs or the phone is charging. Says when a session needs you, fails or is done, over headphones unless Speaker is on. Android's voices first, compared with Kokoro on the phone; no cloud voices. On a locked phone, allow, push and Auto mode need a fingerprint, or a spoken yes over his own earbuds or car; code stays hidden until unlock. Agents started by voice begin in Manual unless he says otherwise and confirms. These were proposed by the agent and accepted when Shankar said to build the design; he can change any of them.
55. **31 Oct 2026. Rocket controls the app the way he would.** It uses the app's own actions, by voice or typing. It can start sessions with any folder, login, model and mode, clone repos with his GitHub accounts, and switch or create branches, in step 5. It starts in Manual unless he names a mode and never picks a less restrictive one itself. Manual and Plan start at once; Accept edits and Auto need a yes (narrows decision 54, which asked for a yes on every mode but Manual). Settings can become tools too, in a later step. Logins, secrets and Rocket's own safety rules stay manual. It doesn't control other apps (decision 51). `docs/assistant.md`.
56. **31 Oct 2026. Rocket learns as he uses it.** Short notes, about 20 at most, on the phone: nicknames for projects, preferences. It asks when it isn't sure, saves what he teaches it in the conversation, and says what it saved; a habit it notices is saved only on a yes. Settings shows every note to edit or delete, with a Refresh projects button. Notes can't remove an approval, and secrets are refused. Step 5. `docs/assistant.md`.
57. **31 Oct 2026. Sensitive actions need a fingerprint, every time.** Destructive actions and messages to other people (delete a branch, force-push, discard changes, send to Slack) show a popup with the exact action and need a fingerprint even on an unlocked phone, with the PIN as fallback. Ignoring it means no. The app decides what is sensitive and unknown actions count as sensitive; Claude and memory can't change that. Push, merge and opening a PR stay on a spoken yes (decision 54). Agents in Auto are covered only as far as a hook can catch them, to be tested in step 5, and he has been told that isn't a guarantee. `docs/assistant.md`.
58. **31 Oct 2026. Rocket opens on the orb.** The start page is a breathing orb, amber when something needs him, with one spoken-style sentence, Deny and Review when needed, and a link to the other sessions in place of a list. Tapping the orb or the mic takes over the screen with the large orb for listening and thinking. Answers show a small orb beside the text, with cards below. Approval uses the large command screen. Replaces the status-list start page in decision 52; the tabs and quick controls stand. `docs/ux-mockup/rocket/home-prototype.html`, `A-Listening`, `A-Show`, `A-Approve`.
59. **31 Oct 2026. Rocket answers only when asked.** After using 1.0.3, Shankar found Rocket annoying: it tracked everything the sessions did and pushed it at him. It is now request and response. No announcements, no session events in its chat, no Allow, Deny or Review on its screen, and it doesn't tell him when something is done: he asks and it checks then. Permission prompts stay with the session that asked, in its own chat and notification. Removes the Announcer behaviour of decision 54 and the amber orb, Deny and Review of decision 58.
60. **31 Oct 2026. Rocket looks like a normal chat.** The orb, the zoomed-in full-screen answers and the cards go. The Rocket tab is a plain chat like the session chat: his messages and Rocket's replies in normal text, every message copyable, a mic in the composer, and a Clear conversation option that empties the chat and starts the brain on a fresh conversation. Its voice is replaced by something less odd, picked in Settings; text first, spoken only when he spoke. Replaces decision 58 and the screen parts of decision 52; the tab stays first.
61. **31 Oct 2026. Rocket is a real agent that delegates.** Rocket can use CLIs (Dockito, git, gh and the rest) and his usual Claude setup instead of only its own app tools, but sends real work to sessions it starts and then reports on, so the work shows in Sessions. It works without asking him at each step; the fingerprint for sensitive actions (decision 57) and on a locked phone stays. Replaces the "no shell, no other tools" lock-down in `docs/assistant.md`. The model, Auto mode with the hook, and Sonnet as its default were proposed by the agent; he can change them.
62. **31 Oct 2026. Hey Rocket is opt-in, and has to actually work.** On his phone with 1.0.3, the model downloaded and "Listening for Hey Rocket" showed, but saying it did nothing. It stays, off by default and never started on its own, and gets fixed and checked on the phone. Replaces the default listening in decision 54.
63. **31 Oct 2026. PocketRocket goes open source, through a fresh repo.** Releases are public and Termux is GPLv3, so the source will be public too, under GPLv3 with Termux's notices kept. It goes out as a new public repo: Termux's history as the base and PocketRocket's work squashed on top, authored with the noreply address, so old commits with his personal email and work references aren't published. Before it's made public, Termux's leftovers (security policy, F-Droid text, issue templates, sponsor images, CI workflows) are replaced or removed, private Dockito doc links are dropped, and he runs gitleaks over what will be published. The private repo stays as it is. Replaces "stays private for now" in decision 30.
64. **31 Oct 2026. Tools shows every tool, one page layout for all.** The tools first-run setup installs show in Tools too, so he knows they're there. Claude and GitHub stay under Accounts in Settings; everything else is a tool, Dockito included, whose login moves from Accounts into its tool page. Tools lists Built in (Node.js and npm, Dockito) and Optional (Headless Chrome, Android build, Android NDK, Wrangler). Every tool page has the same sections, each shown only when it applies: header (what it's for, Built in, Installed or Not installed), Version (installed and latest, Update), Accounts (signed in, default, Add, Sign out), Storage, and Install or Uninstall for optional tools only; built-in tools say they come with PocketRocket. Each tool declares what it supports and one page draws it. The tile line shows an available update first, then who's signed in, then size. The Updates page still lists everything that updates, Claude Code and Git included. Extends decision 39.
65. **31 Oct 2026. One public repo for code and releases, from 1.0.5.** The next release is the open-source launch. The private repo is renamed `pocketrocket-private` and the public `ShankarKakumani/pocketrocket` takes its name; releases and APKs live there, tagged with the matching source.
