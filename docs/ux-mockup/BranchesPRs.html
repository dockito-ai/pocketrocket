Branches and pull requests

Both live in the repo's Git screen, the one you reach from Workspace → repo card (and from the branch in a session's status line). One place per repo, so there is nothing new to find: the branch card at the top opens the branches, and a new PRs tab sits next to Changes and Commits. The Commits tab becomes a Graph. The workspace's GitHub account is used for everything. No creating PRs here.

1 · Where you get in

The workspace's repo cards gain one line when a repo has open PRs. Tapping the card opens the Git screen as today. In a session, tapping the branch in the status line opens the same branch sheet.

3 · Branches

A sheet from the branch card or the status line. Local branches first, newest commit first; remote-only branches below. Tap to switch; long-press for Rename, Delete (only when merged), Compare with current. At the bottom: New branch, and New session on a branch, which opens it in a git worktree so two sessions can work on two branches at once.

4 · A pull request

Read the description, checks and reviews; Files uses the existing diff viewer. At the bottom: Check out (switch this folder to the PR's branch), Review with Claude (a new session on the PR in a worktree, asked to review it), and Merge with the repo's allowed methods. Open on GitHub sits in the ⋮ menu with Close and Mark ready.

5 · Graph

The Commits tab becomes Graph: the commit list with lanes on the left, like GitHub Desktop or git log --graph. Branch names sit on their commits: yours in green, GitHub's (origin/…) in blue, PR numbers in purple. “This branch” or “All branches”. Tap a commit for its files and diffs (as today); long-press for Check out, New branch here, Open PR, Copy SHA.
